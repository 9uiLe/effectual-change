# Moletta Verify

[実行と再開](../moletta/references/workflow.md) と [観測の契約](../moletta/references/record-format.md) を使う。

## 実行前

原文と意図を読み直し、何を観測すればどの要求・成果が満たされるか確認する。実験の合否、範囲、環境、保持・省略条件、否定対照と、対象の実装・設定の版を先に記す。ローカルで追跡すべき入力は `subject.files` に列挙する。

`unit` は部分、`integration` は接続、`end_to_end` は開始から成功までの全体経路とする。観測範囲を後から広げない。操作には既存の権限を使う。

## 実物の観測と判定

[情報の最小化と操作の境界](../moletta/references/security.md) を守り、必要な試験用入力と結果だけを扱う。モバイルは [作業専用の端末](../moletta/references/mobile-environment.md) を使い、他担当の端末や共有 runtime を停止・削除しない。実機でしか確かめられない体験は人の確認範囲として分け、その確認機構は Moletta に追加しない。

- **コマンド**: `capture` で実行し、実際の標準出力・標準エラー・終了状態を保存する。
- **ホストの操作ツール**: 操作前に `begin` し、ブラウザー・画面・機器を利用可能なツールで操作する。その実際の出力・操作履歴を `record` へ渡し、必要な画像やファイルも添付する。意図や想定出力を履歴の代わりに書かない。

観測と実物を読み、事前基準に照らして `assess` で合格・失敗・不明と理由を残す。終了コード 0 や、操作 API の成功だけでは、期待した結果まで成立したことにならない。否定対照が同じ成功を返すなら観測方法を見直す。

性能値は [選択した性能ログの集計](../moletta/references/performance.md) を使い、単位・機種・OS・実機か仮想端末か・シナリオ・収集条件を揃える。未対応の trace や、条件の違う平均値から改善を推定しない。`output_blocked` は証拠本体が保存されていない観測であり、合格にしない。画像等の不透明な添付物は必要性と実際の許可を確認してから取り込む。

スクロールのカクつきは [滑らかさの検証](../moletta/references/scroll-performance.md) を使う。再現操作・測定区間・hitch 指標の取得を確認し、欠測をゼロへ読み替えない。XCTest の継続比較と Instruments の原因調査を必要に応じて接続し、trace の生成だけで計測成功としない。

失敗・不明は消さない。別の適用可能な合格観測で解消を明示する。対象を変えた観測は同一条件の再試行ではなく、計画と対象の適用範囲から再評価する。

## 全体の到達

`check --stage verify` は、選んだ案について、対象環境の合格観測が全要求を覆うかを確認する。成果ごとに、その成果に必要な要求をすべて含む `end_to_end` の合格観測も必要である。未完了・未判定の観測や、未解決の重要指摘も扱う。

結果を取得したら、この run の作業用端末を解放してから最終確認する。正常終了だけでなく失敗・中断時も回収を行い、回収できなければ義務と理由を残す。端末 lease が未解放なら `DEVICE_CLEANUP_PENDING` が最終検査を止める。

準備状況の成功は、意味上の成功や真正性の証明ではない。原文からの欠落、実物の結果、外部の版・追跡外条件をレビューし、達成したことと残る限界を伝える。対象環境で試せなければ、条件付き判断と次の確認を残す。全体試験が成立しなければ、修正だけでなく [探索](../moletta-explore/SKILL.md)・[比較](../moletta-compare/SKILL.md) へ戻る。
