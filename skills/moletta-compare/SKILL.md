# Moletta Compare

原文と固定した意図を読み、[記録形式](../moletta/references/record-format.md) の案と判断を使う。

## 比較の単位

- 接続、運用、移行、費用、失敗時を含め、成果まで働く構成を比較する。課題に重要な条件へ絞る。
- 各要求を満たす仕組み、根拠、未知、違反を並べる。必須能力の欠落を他項目の高得点で相殺しない。
- 方式固有の設計上の義務を、全案の必須要求にしない。局所改善が成果へ寄与しない、新しい事実で優劣が変わる場合は、分解と全体方式を再検討する。
- 重要な別機構の調査がなければ [探索](../moletta-explore/SKILL.md) で補う。好みが不明で結論が変わる場合だけ人に尋ね、技術的な未知は調査や実験にする。

## 原文から反証する

重要な選択や意味の抜けが疑われる場合、[別文脈のレビュー](../moletta/references/delegation.md) で必要能力を再構成する。利用できない場合は自己レビューと明記する。未解決の critical / material 指摘を放置して確定しない。

## 判断を残す

| `decision.status` | 意味 |
| --- | --- |
| `exploring` | 選択を変える問いを調べる |
| `provisional` | 未知と解消条件、不成立時の対応を明示して限定的に進む |
| `selected` | 必須能力に既知の違反がなく、採用する。全体達成の実証は別に判断する |
| `rejected` | 現条件では採用しない |

理由、条件、再考のきっかけと、予算と終了条件付きの `next_action` を一つ記す。`check --stage decide` の結果を原文・根拠と一緒に判断する。全体到達は [検証](../moletta-verify/SKILL.md) で観測から判断し、手入力の完了フラグにしない。
