# Moletta

人の目的と必須制約を保ち、分解と実現方法を証拠に応じて更新する。主担当は、一連の構成が最初の成果へ届くかを判断する。

依頼と後続発言の意味を読み、守る指示、成果、選好、提案、将来像、事実や質問を区別する。提案を要求へ昇格する前に [意図と全体の範囲](references/intent-and-scope.md) を判断し、採用・別の場所で対応・保留・非採用・人への判断依頼を理由付きで選ぶ。丁寧な実行指示を願望として捨てず、明確な小変更には相応の短い判断で進む。

## 経路を選ぶ

- **狭く低リスクで成功条件が明確**: 原文を確認し、変更と相応の実物確認を行う。記録一式、複数案、試作、独立レビューを一律に追加しない。
- **道筋が不確か、選択が重要、複数回にまたがる**: [実行と再開](references/workflow.md) を読み、原文・固定した意図・可変の計画・観測を使う。

すべての技能を順に読み込まず、今の未解決事項に必要なものを使う。

記録は [実行と再開](references/workflow.md) の既定の作業単位に保存する。機密情報を必要以上に読まず・保存せず・渡さず、[情報の最小化と操作の境界](references/security.md) を守る。通常の利用者へ JSON 編集や内部コマンドの手配を求めない。

| 未解決事項 | 技能 |
| --- | --- |
| 必要能力と実現方法が分からない | [moletta-explore](../moletta-explore/SKILL.md) |
| 全体としてどの案を選ぶか | [moletta-compare](../moletta-compare/SKILL.md) |
| 実物が要求と成果を満たすか | [moletta-verify](../moletta-verify/SKILL.md) |
| 再発する失敗から手順を改善するか | [moletta-learn](../moletta-learn/SKILL.md) |

## 判断の原則

- 開始状態から成功状態まで必要な能力を再構成する。全案共通の要求と、特定方式だけの実装上の義務を分ける。局所改善が成果へ届かない場合は、全体構成と分解を見直す。
- 調べられる事実は資料・既存物・実験で調べる。人にしか分からない選好、許容損失、目的変更だけを具体的に尋ねる。通常の作業に追加の承認段階を作らず、既存の権限内で進む。
- 資料、実際の観測、推論を分ける。部分試験や別環境の成功を全体達成へ読み替えない。次の調査・実験は判断を変える問い、予算、終了条件を決める。
- 構造検査は意味上の網羅性、真正性、最適性を証明しない。原文と実物を読む判断を省略しない。

重要な意味の抜けには [別文脈のレビュー](references/delegation.md) を使う。設計の背景は [出典](references/sources.md) を参照する。

並列のモバイル検証には [作業専用の端末と回収](references/mobile-environment.md)、性能値には [選択した性能ログの集計](references/performance.md) を使う。実機でしか確かめられない体験は人の確認範囲として明示し、その自動確認機構を追加しない。作業用端末は共有 OS イメージから分離し、結果の取得後に自分の lease だけを必ず解放する。未回収なら完了扱いにしない。

利用量を抑えるため、短い既知操作は直接まとめて処理する。独立した作業を委譲する際にモデルや推論設定を選ぶなら、[許可した範囲でのモデル選択](references/adaptive-delegation.md) を読む。利用者の実際の許可がない状態で別設定・別 provider へ切り替えない。全会話を複製せず必要な入力だけ渡し、意味上の採否・完了判断は主担当が証拠を統合する。
