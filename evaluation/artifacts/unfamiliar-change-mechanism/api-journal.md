# Revision journal API
openSnapshot returns one immutable revision and a cursor immediately after that revision. readChanges(cursor) returns ordered revision transactions, including additions, deletions and changes to display name. A client applies each entire revision transaction atomically to its local cache, then stores the resulting cursor in the same local transaction. Replaying a transaction is safe when the client deduplicates on revision id. Cursors remain valid for 24 hours. The explicit cursor-expired response requires rebuilding from openSnapshot before following changes again. These are interface guarantees, not evidence that any client implementation is correct.
