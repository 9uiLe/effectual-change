**推奨構成は条件付きです。** ArrivalTap が通知から項目 ID と要求設定を取り出し、ローカルの処理役が PanelHands に操作と Save を指示し、PanelSight が読み取った**保存状態**を要求設定と照合します。一致した場合だけ項目を完了にしてください。処理役は ID ごとの状態を保持し、同じ通知の再到着では操作を重ねず、結果が不明な場合も保存状態を確認してから再試行します。専用アカウントをロック解除状態に保ち、PanelHands に必要なアクセシビリティ権限を付与することが前提です。

**次の最小の検証**は、対象ワークステーションでの一連の実機試験です。保存状態を A にして新規項目で B を要求し、通知から Save、保存状態 B の確認、完了までを観測します。同じ ID を再送して二重操作がないことを確かめ、続けて Save を意図的に無効化した別項目で、保存状態が変わらず完了にもならないことを確認します。

[製品メモ](../../artifacts/arrival-action-verification/product-notes.md)から確立しているのは、既存デモが十件の要求設定を正しく読み取ったことまでです。設定変更、保存、重複防止、無人での完了は未実証で、対象アカウントへの権限付与も未実施です。したがって現時点ではこの構成を実証済みとは判断できません。
