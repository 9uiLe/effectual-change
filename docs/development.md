# 開発・検証・配布

## 実行環境

macOS / Linux、Python 3.11 以上を使用します。実行ツール、導入ツール、評価器は Python 標準ライブラリで動作します。ビルド処理、依存のダウンロード、モデル認証は開発用の自動検査に不要です。

```sh
python3 scripts/validate.py
```

この入口をローカルと CI で共用します。実際の配布物の名前・必要メタデータ・相対参照・プラグイン manifest、公開コーパス、`tests/` のテストを検査します。失敗すると非ゼロで終了します。モデルの判断や GUI の意味上の成功を自動採点する入口ではありません。

## 配置

| 場所 | 内容 |
| --- | --- |
| `skills/moletta/` | 入口、共有の操作・データ契約、runtime |
| `skills/moletta-*/` | 探索・比較・検証・改善の判断方針 |
| `scripts/` | 配布内容の検査、プロジェクトへの導入、共通検証入口 |
| `evaluation/` | コーパス、非公開 rubric を除いたパケット生成、判定の比較 |
| `tests/` | runtime、配布、導入、評価器の仕様・境界検査 |
| `docs/` | 要件、設計理由、評価・開発方法 |

## テストの保証責任

runtime のテストは状態遷移、意図・実験・対象・観測の対応、失敗の保持、対象変更、CLI の保存・再開を確認します。workspace のテストは worktree ごとの保存先、独立 ID、README、明示 RUN、`.gitignore` の非変更を扱います。入力保護は選択パス・サイズ上限・既知の秘密値・`output_blocked` の合格拒否を確認します。

端末のテストは合成ホストコマンドを使い、共有 OS と独立データ、所有確認、ポートの競合、失敗時の記録、解放の再試行、回収の範囲を扱います。性能集約は合成の数値 fixture で形式、統計、条件一致、非対応入力の拒否を確認します。担当の予約は合成 catalog と承認記録で選択範囲、期限、予算、並列数、未知の使用量を確認します。これらは実機 UX、実ホストでの端末起動、実アプリの性能改善、実際のユーザー承認の認証を証明しません。

導入テストは実ファイルを使い、両ホスト・配置方法・衝突時の非上書きを確認します。配布検査は人工 fixture と別に、実際に出荷する技能と相互参照を確認します。評価器のテストは一時的な合成判定を使い、パケットの分離と比較の規則を確認します。

技能の効果は [行動評価](evaluation.md) で測ります。構造検査の成功を効果測定へ読み替えません。重要な判断方針を変える場合は、独立文脈の実行、独立採点、費用、軽い依頼への過剰適用も確認します。

発言の意味や案の採否は固定語句の分類テストにしません。公開の行動ケースで願望・明確な指示・制約衝突を区別し、実際の結論と変更成果物を確認します。少数のケースでの動作確認は、同条件の基準版比較や未見ケースを使った改善評価とは区別します。

## 配布と更新

checkout 自体を配布物とします。ホスト用の技能は installer で一式を配置します。Claude Code のプラグイン経路は同じ `skills/` を参照し、別の指示や runtime を持ちません。marketplace や外部への公開を自動で行う仕組みはありません。

配布する技能の一覧は `scripts/distribution.py` が定義します。技能の frontmatter は、フォルダー名と一致する `name` と、使用場面を表す `description` を、それぞれ単一行の文字列で記します。技能の相対参照は導入される `skills/` 内で完結させます。

共有する checkout を更新する前に共通検証を実行します。リンク導入は次の読み込みからその checkout の内容を使います。コピー導入は導入先の内容を確認して削除し、再導入します。既存の設定・技能への自動移行や上書きは行いません。

## ローカル記録とホスト状態

`init` は既定で現在の Git worktree のルートへ `.moletta-runs/<作業単位ID>/` を作ります。Git の外では選択したプロジェクトまたは呼び出し元のディレクトリを使います。`.moletta-runs/README.md` に用途を説明し、`/.moletta-runs/` を `.gitignore` に加えるよう案内します。除外設定そのものは変更しません。明示 RUN は既定の保存先を使わず、既存の作業を上書きしません。

実行記録には依頼、操作履歴、標準出力、観測ファイル、性能集約、担当の予約・使用量が含まれ得ます。機密資料として扱い、案件の保存方針に従って保持・削除します。公開 fixture には合成の ID と値を使い、実案件の記録を配布物へ入れません。[入力と情報境界](../skills/moletta/references/security.md) は限定的な入力保護とホストの権限の違いを定義します。

端末 lease の共有 registry はホスト上に置き、作業単位内の `devices/` に所有 receipt を残します。installed runtime / system image は共有し、作業ごとの可変データを lease で分離します。観測後は必ず対象 lease を解放し、失敗した解放は `cleanup_pending` のまま追跡します。`device gc` の既定は候補表示です。存続する作業の端末を経過時間だけで削除しません。

性能の形式と比較条件は [performance.md](../skills/moletta/references/performance.md)、担当の承認・host catalog・予算は [adaptive-delegation.md](../skills/moletta/references/adaptive-delegation.md) を参照してください。実ホストで確認した能力と未確認の能力を区別し、自動検査の成功を実運用の完了へ読み替えません。
