# 設計上の判断

## 成果と構成の責任

対象は、明確な目的に向けた AI 開発で、要求の欠落、未知の方式、比較軸の不足、試作からの過剰な一般化を扱うこと。主担当は、部品の採用結果を集めるだけでなく、一連の構成が元の成果を実現するかを判断する。

固定するのは人の目的・必須制約。分解、導出要求、方式、実装順序は証拠で更新できる。局所改善が成果に寄与しない、回避策が増える、新しい事実で全体案の優劣が変わる場合は、構成から比較し直す。人の必須条件を外す案は、条件変更が必要な案として扱い、自動採用しない。

## 一つの入口と必要時だけ読む技能

全指示を一枚に集める方式は、単純作業にも重い手順を適用しやすく、修正影響も読み取りにくい。そのため入口と探索・比較・検証・改善を分ける。ホスト固有のサブエージェント定義やモデル名はコアに含めない。利用可能なら別文脈の検討を使い、使えない場合は自己点検と明示する。

技能間の相対参照は、全 sibling を一緒に配置するインストーラーが維持する。配布時に個別技能を切り離さない。Claude のプラグイン形式でも、同じコアを参照する。

## 実行ツールの保証範囲

Python 標準ライブラリだけで、リンク関係、固定した意図、捕捉したコマンドの条件と出力、証拠の範囲を検査する。エージェントが書いた「成功」という説明と、コマンドの観測記録を分ける。判定基準や実験環境を事後に変更した場合、古い捕捉を新しい実験へ流用できない。

原文から能力を一つも抽出しなかった場合、その意味上の欠落を構造検査だけでは判定できない。URL が根拠を支持するか、観測方法が正しいか、実環境との差が重要かもエージェントが読む必要がある。独立した文脈の原文レビューと、合成ケースによる行動評価がこの範囲を受け持つ。

現版の capture はコマンド実行を対象とする。GUI や外部機器を検証する場合は、観測を取得する案件固有のコマンドまたは追加の取り込み手段が必要。観測手段が未実装なら、その能力を検証済みと扱わない。任意の動画ファイルを measurement として受け入れることで、この未解決を隠さない。

## 改善の単位

失敗のたびに全タスク共通の規則を足す方式は採らない。失敗の適用条件を記録し、必要な技能か構造検査の小さい変更として比較する。軽い依頼を正しく終えるケースも評価対象に含める。行動評価の結果がまだない変更を、精度が改善したと宣伝しない。

## 互換性

Codex は `.agents/skills/`、Claude Code は `.claude/skills/` から同じ Agent Skills を利用する。読み込み・発火の判断は各ホストが行う。プラグイン manifest は Claude Code の任意の読み込み経路で、常駐プロセス、MCP サーバー、権限設定、フックを導入しない。主担当が利用可能なツールでローカルコマンドを実行する。

配置と呼び出しの仕様は [Codex skills](https://learn.chatgpt.com/docs/build-skills)、[Claude Code skills](https://code.claude.com/docs/en/skills)、[Claude Code plugins](https://code.claude.com/docs/en/plugins) を参照。現版で実際に確認した範囲は [検証記録](validation.md) に記載する。
