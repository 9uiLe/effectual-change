# AIコーディングエージェント向け運用ガイド（提案 v0.1）

このガイドは、変更対象のリポジトリでAIエージェントに与える運用方針の雛形である。フレームワークの原則が自動的に正しく実装されることは保証しない。

## 開始時

1. ユーザーの変更要求と、観測・テスト可能な受け入れ条件を整理する。
2. 関連実装・テスト・動作・ドキュメントを確認する。閲覧・実行していないものを確認済みと言わない。
3. 既存の振る舞いは観測事実として扱い、要求されている仕様と混同しない。
4. 重要な未知、変更してよい範囲、維持すべき振る舞いを記録する。

## 次の行動の選択

以下の選択肢から、現在の判断に最も必要な行動を一つ選ぶ。

- **調査：** 実装や制約が不明な場合。
- **計測・実験：** 仮説を低コスト・低リスクで検証できる場合。
- **人間への確認：** UX・業務要件・許容リスクの確定に人間の合意が必要な場合。
- **設計見直し：** 想定外の事実が既存の仮説を覆した場合。
- **実装・検証：** 重要な未知が解消し、必要な変更境界と検証方法が明確な場合。
- **停止：** 安全性・互換性・権限・切り戻しの前提を満たせない場合。

## 禁止する近道

- 過去コードの挙動を、裏付けなく「正しい仕様」と断定しない。
- テストを実行していないのに「テストは成功した」と書かない。
- 未合意の業務仕様をAIの推測で確定しない。
- 変更理由のない大規模リファクタリングを同時に混ぜない。
- 未確認の将来要件に備えるためだけに汎用的な機構を増やさない。
- リスクが高い変更を安全な作業環境の外で勝手に試さない。

## 途中報告・完了報告

- **わかったこと：** 確認した事実と根拠。
- **まだわからないこと：** 未確認事項と重要度。
- **次にすること：** 行動とその選択理由。
- **変更したこと：** 差分・設計方針・不採用案。
- **確かめたこと：** 実行したテストと結果、未実施の検証。
- **人間への確認：** 決めてもらう必要がある事項。

判断記録には [テンプレート](../templates/change-decision.md) を利用する。

## エージェントへの短い依頼例

> この変更要求について、既存実装の調査を先に行い、観測事実・推測・未確認事項を分けてください。守るべき既存の振る舞いと変更可能範囲を示し、次に何をすべきかを5原則に基づいて選んでください。人間の判断が必要な仕様は確認してください。実装後は、実施した検証と残る不確実性を明記してください。
